HMWK 2 - From Wallet Seed to Ethereum Address


Hashing, key derivation and cryptographic primitives


1. The big picture


An Ethereum wallet looks like it just gives you twelve words and an address, but a few different steps sit between the two. Only the first one is random. After that everything is calculated from the step before, so the same words always give the same address.


    
  
  1. Random bits are turned into a mnemonic of 12 to 24 words (BIP-39).
    2. 
  
  2. The mnemonic is stretched into a 512-bit seed (also BIP-39).
    3. 
  
  3. The seed is used to derive a private key along a fixed path (BIP-32 and BIP-44).
    4. 
  
  4. The private key gives a public key on an elliptic curve (secp256k1).
    5. 
  
  5. The public key is hashed with Keccak-256 and the last 20 bytes are the address.
    6. 
  
  6. The letters in the address get upper or lower case based on another hash, so typos can be caught (EIP-55).
    7. 




2. What each piece does


BIP-39. This is the part that makes a backup possible for a normal person. 128 to 256 random bits get a small checksum added (the first few bits of their SHA-256 hash), then the bits are cut into groups of 11 and every group picks a word from a list of 2048. That gives 12 words for 128 bits and 24 words for 256 bits. To get the seed, the words are put through PBKDF2 with HMAC-SHA512, 2048 rounds, which gives 64 bytes. There is also an optional passphrase, sometimes called the 25th word, that changes the seed completely.


BIP-32. One seed can produce a whole tree of keys. The master key comes from HMAC-SHA512 of the seed (the left 32 bytes are the key, the right 32 bytes are the chain code). Each child key is computed from the parent key, the chain code and an index. Indexes from 231 up are called hardened, and they use the parent's private key, so someone who only has a public key cannot derive them.


BIP-44. BIP-32 does not say which branch of the tree to use, and BIP-44 fixes that so every wallet agrees. The path is m / 44' / 60' / 0' / 0 / 0, which means purpose, coin type (60 is Ethereum), account, change, and address index. Adding a new account in a wallet usually just increases the last number.


secp256k1. This is the elliptic curve Ethereum uses (the same one as Bitcoin). The private key is a big number k, and the public key is the point k times G, where G is a fixed starting point on the curve. Going forward is easy, but getting k back from the public key is the discrete logarithm problem, which is believed to be too hard to solve. The same keys are also used to sign transactions.


Keccak-256. A hash function with a 256-bit output. Ethereum hashes the 64 bytes of the public key (x and y) and keeps only the last 20 bytes, which is the address.


EIP-55. The address is written in lower case hex, hashed again with Keccak-256, and every letter (a to f) is made upper case if the matching hash digit is 8 or more. The address is still the same address, but now the case pattern works as a checksum. If someone mistypes a character, the pattern usually stops matching and the wallet can warn them.



3. Telling the ideas apart


These are easy to mix up, so here is how I separate them:


    
  
  • Key generation means making a brand new secret from real randomness. In the pipeline this only happens once, at the very start, when the entropy for the mnemonic is picked.
    • 
  
  • Key derivation means computing keys from a secret you already have. It is repeatable: same input, same output. The seed, the master key and the child keys are all derived.
    • 
  
  • Public-key cryptography is the secp256k1 part. The private and public key are linked mathematically, so you can prove you own a key (by signing) without showing it.
    • 
  
  • Hashing takes any input and gives a fixed-size fingerprint. There is no key and no way back. Keccak-256 does it for the address, and SHA-512 is used inside BIP-32 and BIP-39.
    • 
  
  • Checksums only exist to catch mistakes. They add no secrecy. The last bits of the mnemonic and the letter case in EIP-55 are both checksums.
    • 
  
  • Encoding changes how something is written without changing what it is: bits to words, bytes to hex, lower case to mixed case. It can always be reversed.
    • 



One detail worth noting: the mnemonic is an encoding of the entropy, but the seed is not decoded from the words. It is derived from the text of the words with PBKDF2, so that step belongs to derivation.

I also measured a few statistical properties:


    
  
  • Avalanche. Flipping one bit of a 512-bit input changed 128.25 of the 256 output bits on average over 2,000 tries (standard deviation 8.12). A perfect random function would give 128 and 8.
    • 
  
  • Balance. Over 20,000 random hashes, 49.993% of the output bits were 1.
    • 
  
  • Uniformity. A chi-square test on 640,000 output bytes gave 238.2, and the expected value is about 255, so nothing looks biased.
    • 
  
  • EIP-55. Changing one character of a checksummed address was caught 19,995 times out of 20,000 (99.975%). An address has about 15 letters on average, and each letter's case works like one checksum bit, so a typo gets through roughly 1 time in 4,000. Addresses with few letters are protected less.
    • 
  
  • Sizes. 12 words are 128 bits of entropy (about 3.4 x 1038 options) and 24 words are 256 bits. A private key is a number just under 2256, and an address has 160 bits.
    • 



These tests only show that there is no visible bias. They do not prove security, and none of the later steps can add randomness, so if the first 128 bits are weak every key made from them is weak too.



5. Timeline and SHA-2 vs Keccak


Putting the pieces in order shows that the pipeline was built in layers over a long time (years are approximate):



  
YearWhatWhy it matters here

  
1977RSAFirst well-known public-key system, not used in the wallet itself

  
2001SHA-2 / SHA-512Used inside BIP-32 and BIP-39

  
2012BIP-32Hierarchical deterministic wallets

  
2013BIP-39Mnemonic words and the seed

  
2014BIP-44Standard derivation paths

  
2015SHA-3 standardizedEthereum had already launched with the original Keccak

  
2016EIP-55Mixed-case checksum for addresses




There is a long gap after RSA and then almost everything wallet-related shows up between 2012 and 2016, which fits with Bitcoin making people care about backing up keys. RSA is missing from the wallet because it needs much bigger keys (around 3,072 bits) for about the same security as a 256-bit elliptic-curve key.


SHA-2 and Keccak are both hash functions but they are built differently. SHA-2 (Merkle-Damgard) processes the message block by block, and SHA-512 gives 512 bits. Keccak uses a sponge: the message is absorbed into a big internal state and then the output is squeezed out. NIST picked Keccak in 2012 as the basis for SHA-3. When it was standardized in 2015, NIST added two extra domain-separation bits, which changes the padding byte from 0x01 to 0x06. Ethereum was already using the original version, so Keccak-256 and SHA3-256 give different outputs for the same input. For the empty string my run gave:


Keccak-256:  c5d2460186f7233c927e7db2dcc703c0e500b653ca82273b7bfad8045d85a470
SHA3-256:    a7ffc6f8bf1ed76651c14756a061d662f580ff4de43b49fa82d80a4b80f8434a


So using a standard SHA3-256 function to build an Ethereum address would give a wrong address.



6. Why not just one algorithm?


Because each step solves a different problem and no single algorithm does all of them. A hash cannot sign anything, a signature scheme cannot turn a backup into twelve words, and a checksum does not protect any secret.


    
  
  • BIP-39, BIP-32, BIP-44 handle key management: one short backup that can rebuild a whole tree of keys, in the same place in every wallet.
    • 
  
  • secp256k1 gives the link between private and public key, so you can sign a transaction and others can check it without learning the secret.
    • 
  
  • Keccak-256 shrinks the 64-byte public key to a short fixed-size 20-byte address.
    • 
  
  • EIP-55 catches typing mistakes, which matters a lot because a transaction sent to a wrong address cannot be undone.
    • 



It is also partly history. The first four steps come from the Bitcoin world and use SHA-512 inside, and the last two were added for Ethereum with Keccak, which is why one wallet ends up using two different hash families.


To see this in a real wallet, create a throwaway wallet in MetaMask (no real money), reveal its 12-word recovery phrase, and import the same phrase into Rabby. The first address will be identical because both follow m/44'/60'/0'/0/0. Adding a second account gives a new address from the same phrase, which is the same path with the last index set to 1. The mixed upper and lower case in the displayed address is EIP-55, and changing the case of one letter in a pasted address usually makes the wallet reject it.
